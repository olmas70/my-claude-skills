## 프로젝트 개요

- 무엇을 하는 프로젝트인지 한두 문장
- 주요 기술: (예: Node 20, Express, PostgreSQL)
- 패키지 매니저: (예: pnpm)

## 자주 쓰는 명령어

```bash
pnpm install        # 의존성 설치
pnpm dev            # 개발 서버
pnpm test           # 테스트 전체
pnpm test -- <파일>  # 테스트 하나만
pnpm lint           # 린트
pnpm build          # 빌드
```

## 폴더 구조

- `src/` 소스 코드
- `src/api/` API 라우트
- `tests/` 테스트 (`src/` 구조를 그대로 따름)
- `docs/` 문서

## 코딩 규칙

- 파일 이름: 소문자-하이픈 (예: `user-service.ts`)
- 함수는 50줄, 파일은 800줄 넘지 않게
- 객체는 수정하지 말고 새로 만들어서 반환 (불변성)
- 비밀값은 환경변수로만. 코드에 직접 쓰지 않기

## 작업 흐름

1. 3개 이상 파일을 바꾸는 작업은 먼저 계획을 보여주고 승인받기
2. 테스트를 먼저 쓰고 구현하기
3. 완료라고 하기 전에 `pnpm test`와 `pnpm lint`를 실제로 실행해 결과 보여주기
4. 커밋 메시지: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`

## 하지 말 것

- 요청하지 않은 파일·서식·주석 손대지 않기
- `main` 브랜치에 직접 커밋하지 않기
- `.env` 파일 읽거나 커밋하지 않기
